# 작업공간 화면 설계

요건 정의 12장의 작업공간(화면 출력부)이 어떻게 보이고 어떻게 조작되는지 정합니다. 서버의 상태 모델은 기술 설계 4.15, 보안 규칙은 `보안 설계.md`, 디렉터리와 실행 방법은 실행 설계를 따릅니다. 문서가 충돌하면 요건 정의, 기술 설계, 실행 설계, 보안 설계, 이 문서 순으로 따릅니다.

"측정 대기"로 표시한 항목은 구축 절차 4.3의 측정 결과로 채운 뒤에 지시서에 씁니다.

## 1. 목적과 범위

- 파이프라인과 외부 에이전트를 한 화면에서 조작하고 관찰합니다.
- Windows, iPhone, iPad에서 같은 기능, 같은 작업공간 상태, 같은 조작 모델을 제공합니다. 화면 크기와 입력 수단에 따라 배치만 달라집니다(요건 NF-7).
- v1은 보기 전용과 터미널 연결입니다. orch 명령 실행, 외부 에이전트, 도구 호출 관찰은 v2입니다(요건 12장).

## 2. 패널

패널은 작업공간의 가장 작은 화면 단위입니다. 한 패널은 아래 종류 중 하나를 보여 줍니다.

| 패널 | 내용 | 요건 | 범위 |
| --- | --- | --- | --- |
| 터미널 | tmux 세션 `orch-<대상>`의 창. 메인 Claude Code, D 레인 패널 | WS-2, WS-3 | v1 |
| 작업 보드 | 상태별 열, 대기 사유, 막힌 의존 사슬, 새 배분 중단 사유 | BL-1 | v1 |
| 실행 로그 | 실행 중인 회차의 로그. 실행이 시작되면 자동으로 열리고 끝나면 표시 | BL-2 | v1 |
| 작업 상세 | 지시서, 결과 보고, G1~G3, 리뷰 판정과 triage, 회차 기록 | BL-3 | v1 |
| diff | 작업 diff, 리뷰 diff (읽기 전용) | BL-4 | v1 |
| 프로세스 | 실행 중인 서브의 pid, 경과 시간, 시간 제한까지 남은 시간, CPU | BL-5 | v1 |
| 병합 표 | PR, Head, Base, Tests, Lint, Gates, Review, Merge by. GitHub 링크만, 머지 버튼 없음 | OR-1 | v1 |
| 운용 상태 | doctor 항목과 수준, 새 배분 중단, 서비스 세션 생존 | OR-3 | v1 |
| 에이전트 | 설치·기준·지금·최신 버전, selfcheck 후보와 항목별 결과, 토큰 사용량, 한도 | AG-1~5 | v1 |
| 진행도 | 페이즈 파이프라인, 마일스톤별 작업 상태와 진척률 | PG-1, PG-2 | v1 |
| 실행 기록 | runs와 게이트 결과 필터 | BL-6 | v2 |
| 외부 에이전트 세션 | ACP 세션의 대화, 도구 호출, 권한 요청 | EX-1 | v2 |
| 도구 호출 | 세션별 도구(MCP 포함) 호출, 소요 시간, 성공 여부, 크기 | MC-1 | v2 |

## 3. 배치 개념

Hyprland는 도입하지 않습니다(Linux Wayland 전용 창 관리자). 조작 개념과 시각적 느낌만 가져와 작업공간 앱 창 하나 안에서 구현하며, OS의 다른 앱 창은 배치하지 않습니다.

| 개념 (Hyprland 용어) | 작업공간에서의 모습 | 구현 |
| --- | --- | --- |
| 타일 | 패널 하나 | 클라이언트가 그리는 화면 요소, 내용은 서버 데이터 |
| dwindle 레이아웃 | 새 패널이 포커스된 패널을 반으로 나눔, 분할 방향이 번갈아 바뀜 | 서버가 가상 화면마다 분할 트리(노드 = 방향과 비율, 잎 = 패널)를 가짐. 클라이언트는 그리기만 함 |
| master 레이아웃 | 큰 주 패널 하나와 나머지를 옆에 쌓은 배치 | 같은 트리를 다른 규칙으로 배치, 가상 화면마다 선택 |
| 가상 화면 (workspace) | 패널 묶음. 기본으로 대상마다 하나, 사용자가 추가 가능 | 가상 화면 목록과 각 분할 트리를 서버가 가짐 |
| 플로팅 | 트리에서 빼내 위에 띄운 패널 | 트리 밖 목록, 위치와 크기 저장 |
| 스크래치패드 (special workspace) | 한 번의 조작으로 띄웠다 숨기는 겹침 화면. 승인 대기(OR-2), doctor 경고. 새 셸을 띄우는 "빠른 터미널"은 두지 않음(`보안 설계.md` 4장) | 특별한 가상 화면 하나. 넓은 화면은 가운데 겹침 창, iPhone은 아래에서 올라오는 시트 |
| 시각 효과 | 패널 사이 간격, 둥근 모서리, 포커스 테두리 그라데이션, 열기·닫기·이동 애니메이션, 앱 안 배경의 블러 | 클라이언트 그리기 설정. OS의 "동작 줄이기" 설정을 따름 |

**공유 상태**: 가상 화면 목록, 분할 트리, 플로팅 패널, 열린 패널과 내용, 지금 보고 있는 가상 화면, 포커스된 패널을 모든 기기가 공유합니다. 한 기기의 조작이 다른 기기 화면에 그대로 반영됩니다(ADR 0007).

## 4. 조작

모든 동작은 키보드와 터치 양쪽으로 할 수 있습니다(요건 WS-6).

**키보드**: 리더 키 하나를 누른 뒤 명령 키를 누릅니다. Windows 키와 Super는 OS가 가로채므로 쓰지 않습니다. 기본 리더 키와 브라우저·OS가 가로채지 않는 명령 키 목록은 측정 대기(W-M6)이며, 단축키는 설정 파일로 바꿀 수 있습니다.

| 동작 | 키보드 | 터치 |
| --- | --- | --- |
| 가상 화면 전환 | 리더 + 숫자 | 가상 화면 목록에서 선택, 가장자리 스와이프 |
| 패널 열기 | 리더 + 패널 종류 키 | 명령 팔레트 |
| 패널 닫기 | 리더 + 닫기 키 | 패널 메뉴 |
| 포커스 이동 | 리더 + 방향키 | 패널 탭, 좁은 화면에서는 스와이프 |
| 분할 비율 조절 | 리더 + 크기 조절 모드 | 경계 드래그 |
| 레이아웃 전환 (dwindle, master) | 리더 + 레이아웃 키 | 명령 팔레트 |
| 플로팅 전환 | 리더 + 플로팅 키 | 패널 메뉴 |
| 스크래치패드 열고 닫기 | 리더 + 스크래치패드 키 | 상단 버튼, 아래에서 위로 쓸어 올리기 |
| 명령 팔레트 | 리더 + 팔레트 키 | 상단 버튼 |

**터미널 입력(터치 기기)**: 화면 키보드 위에 Ctrl, Esc, Tab, 방향키를 담은 보조 키 줄을 둡니다. iPad의 하드웨어 키보드가 연결되면 키보드 입력을 그대로 보냅니다(요건 WS-9).

**입력 권한과 입력 소유권** (`보안 설계.md` 4장)

- 터미널 입력은 `입력` 권한을 가진 기기만 할 수 있습니다. `보기` 기기의 터미널 패널에는 보조 키 줄과 입력 칸을 두지 않고, 권한이 없다는 표시만 둡니다.
- 터미널 패널마다 입력 소유 기기가 하나입니다. 패널 머리에 소유 기기 이름을 보이고, 다른 기기는 패널 메뉴나 명령 팔레트의 "입력 가져오기"로 소유권을 옮깁니다. 옮기면 이전 소유 기기에 알립니다.
- 소유하지 않은 기기에서 입력하면 서버가 거부하고 그 기기에만 알립니다.
- 입력 잠금(`orch workspace lock`) 중에는 모든 터미널 패널 머리에 잠금 표시를 두고 입력 칸을 막습니다. 화면에서 잠금을 풀 수 없습니다.
- 창의 프로세스가 끝난 터미널 패널은 읽기 전용으로 바뀌고 끝났다는 표시를 둡니다.

**"이 기기만" 보기**: 명령 팔레트로 켜면 이 기기는 공유 상태의 가상 화면 전환과 포커스를 잠시 따라가지 않고, 이 기기의 조작도 다른 기기에 보내지 않습니다. 화면 위쪽에 켜져 있다는 표시를 두고, 끄면 공유 상태로 돌아옵니다. 모든 기기에 같은 조작으로 있습니다.

## 5. 기기별 배치

| 화면 | 배치 |
| --- | --- |
| 넓은 화면 (Windows, iPad 가로·세로) | 분할 트리를 그대로 타일로 그림 |
| 좁은 화면 (iPhone 세로) | 같은 분할 트리에서 포커스된 패널 하나를 전체 화면으로 그림. 스와이프는 트리 순서상 옆 패널로 포커스를 옮김. 트리 자체는 바꾸지 않음 |
| 공통 | 같은 패널 종류, 같은 명령, 같은 공유 상태. 기기별 전용 기능 없음 |

iPhone에서 포커스를 옮기면 공유 상태에 따라 다른 기기의 포커스도 옮겨집니다.

## 6. 인수 시나리오 (NF-7 출시 조건)

v1은 Windows, iPhone, iPad 세 기기에서 아래 시나리오를 모두 통과해야 출시합니다.

1. 접속과 인증: Tailscale 안에서 접속하고, 허용되지 않은 기기는 거부됨
2. 가상 화면: 대상별 가상 화면이 보이고 전환됨. 한 기기의 전환이 다른 기기에 반영됨
3. 패널: 각 v1 패널을 열고 닫고, 포커스를 옮기고, 분할 비율을 바꿈
4. 터미널: 메인 Claude Code 창에 입력하고 출력이 모든 기기에 보임. 터치 기기에서 보조 키 줄로 Ctrl·Esc·방향키 입력
5. 실시간 갱신: 작업 상태가 바뀌면 보드와 로그 패널이 갱신됨. 연결을 끊었다 다시 붙으면 놓친 이벤트가 채워짐
6. 승인 대기: 메인이 권한 승인을 기다리면 스크래치패드에 표시되고, 누르면 메인 터미널로 이동함
7. 재접속: 화면 잠금·앱 전환 뒤 다시 열면 같은 상태로 돌아옴
8. 비공개 정보: 화면 어디에도 토큰, 알림 토픽, 개인 경로가 나오지 않음. 연결을 끊은 뒤 기기의 브라우저 저장소에 로그와 diff가 남지 않음
9. 입력 권한: `보기` 기기는 터미널에 입력할 수 없음. 소유하지 않은 기기의 입력은 거부되고 그 기기에 알림이 옴. 입력마다 감사 기록이 남고 내용은 남지 않음
10. 입력 잠금: `orch workspace lock` 뒤 모든 기기의 입력이 거부되고, 화면에서 풀 수 없음. 서버를 다시 띄워도 잠금이 유지됨
11. 셸 복귀 없음: 메인 Claude Code를 끝낸 창의 패널이 읽기 전용이 되고 셸 프롬프트가 나오지 않음
