# 작업공간 화면 설계

요건 정의 12장의 작업공간(화면 출력부)이 어떻게 보이고 어떻게 조작되는지 정합니다. 색, 간격, 그림자, 블러, 배경화면, 애니메이션의 값은 `시각 설계.md`, 서버의 상태 모델은 기술 설계 4.15, 보안 규칙은 `보안 설계.md`, 디렉터리와 실행 방법은 실행 설계를 따릅니다. 문서가 충돌하면 요건 정의, 기술 설계, 실행 설계, 보안 설계, 이 문서, 시각 설계 순으로 따릅니다.

"측정 대기"로 표시한 항목은 구축 절차 4.3의 측정 결과로 채운 뒤에 지시서에 씁니다.

## 1. 목적과 범위

- 파이프라인과 외부 에이전트를 한 화면에서 조작하고 관찰합니다.
- Windows, iPhone, iPad에서 같은 기능, 같은 작업공간 상태, 같은 조작 모델을 제공합니다. 화면 크기와 입력 수단에 따라 배치만 달라집니다(요건 NF-7).
- v1은 보기 전용과 터미널 연결입니다. orch 명령 실행, 외부 에이전트, 도구 호출 관찰은 v2입니다(요건 12장).

## 2. 패널

패널은 작업공간의 가장 작은 화면 단위입니다. 한 패널은 아래 종류 중 하나를 보여 줍니다.

| 패널 | 내용 | 요건 | 범위 |
| --- | --- | --- | --- |
| 터미널 | tmux 세션 `orch-<대상>`의 창. 메인 Claude Code, D 레인 패널 | WS-2, WS-3 | v1 |
| 작업 보드 | 상태별 열, 대기 사유, 막힌 의존 사슬, 새 배분 중단 사유 | BL-1 | v1 |
| 실행 로그 | 실행 중인 회차의 로그. 실행이 시작되면 자동으로 열리고 끝나면 표시 | BL-2 | v1 |
| 작업 상세 | 지시서, 결과 보고, G1~G3, 리뷰 판정과 triage, 회차 기록 | BL-3 | v1 |
| diff | 작업 diff, 리뷰 diff (읽기 전용) | BL-4 | v1 |
| 프로세스 | 실행 중인 서브의 pid, 경과 시간, 시간 제한까지 남은 시간, CPU | BL-5 | v1 |
| 병합 표 | PR, Head, Base, Tests, Lint, Gates, Review, Merge by. GitHub 링크만, 머지 버튼 없음 | OR-1 | v1 |
| 운용 상태 | doctor 항목과 수준, 새 배분 중단, 서비스 세션 생존 | OR-3 | v1 |
| 에이전트 | 설치·기준·지금·최신 버전, selfcheck 후보와 항목별 결과, 토큰 사용량, 한도 | AG-1~5 | v1 |
| 진행도 | 페이즈 파이프라인, 마일스톤별 작업 상태와 진척률 | PG-1, PG-2 | v1 |
| 실행 기록 | runs와 게이트 결과 필터 | BL-6 | v2 |
| 외부 에이전트 세션 | ACP 세션의 대화, 도구 호출, 권한 요청 | EX-1 | v2 |
| 도구 호출 | 세션별 도구(MCP 포함) 호출, 소요 시간, 성공 여부, 크기 | MC-1 | v2 |

## 3. 배치 개념

Hyprland는 도입하지 않습니다(Linux Wayland 전용 창 관리자). 조작 개념과 시각적 느낌만 가져와 작업공간 앱 창 하나 안에서 구현하며, OS의 다른 앱 창은 배치하지 않습니다.

| 개념 (Hyprland 용어) | 작업공간에서의 모습 | 구현 |
| --- | --- | --- |
| 타일 | 패널 하나 | 클라이언트가 그리는 화면 요소, 내용은 서버 데이터 |
| dwindle 레이아웃 | 새 패널이 포커스된 패널을 반으로 나눔. 분할 방향은 나뉘는 패널의 가로세로 비율로 정함(3.2) | 서버가 가상 화면마다 분할 트리(노드 = 방향과 비율, 잎 = 패널)를 가짐. 클라이언트는 그리기만 함 |
| master 레이아웃 | 큰 주 패널 하나와 나머지를 옆에 쌓은 배치 | 같은 트리를 다른 규칙으로 배치, 가상 화면마다 선택 |
| 가상 화면 (workspace) | 패널 묶음. 기본으로 대상마다 하나, 사용자가 추가 가능 | 가상 화면 목록과 각 분할 트리를 서버가 가짐 |
| 플로팅 | 트리에서 빼내 위에 띄운 패널 | 트리 밖 목록, 위치와 크기 저장 |
| 고정 (pin) | 모든 가상 화면에서 항상 위에 보이는 플로팅 패널(3.4) | 가상 화면 밖의 목록 |
| 전체화면 (fullscreen 0, 1) | 패널 하나를 크게 보는 두 모드: 전체화면과 최대화(3.3) | 가상 화면마다 패널 id와 모드. 분할 트리는 바꾸지 않음 |
| 스크래치패드 (special workspace) | 한 번의 조작으로 띄웠다 숨기는 겹침 화면. 승인 대기(OR-2), doctor 경고. 새 셸을 띄우는 "빠른 터미널"은 두지 않음(`보안 설계.md` 4장) | 특별한 가상 화면 하나. 넓은 화면은 가운데 겹침 창, iPhone은 아래에서 올라오는 시트 |
| 시각 효과 | 패널 사이 간격, 둥근 모서리, 포커스 테두리 그라데이션, 그림자, 열기·닫기·이동 애니메이션, 패널 뒤 배경의 블러, 배경화면(3.5) | 클라이언트 그리기 설정. OS의 "동작 줄이기"와 "투명도 줄이기" 설정을 따름 |

**공유 상태**: 가상 화면 목록, 분할 트리, 레이아웃 선택, 플로팅 패널, 고정 패널, 전체화면 상태, 열린 패널과 내용, 지금 보고 있는 가상 화면, 포커스된 패널, 배경화면을 모든 기기가 공유합니다. 한 기기의 조작이 다른 기기 화면에 그대로 반영됩니다(ADR 0007, 0021). 효과 수준(3.5)만 기기마다 따로 둡니다(ADR 0023).

### 3.1 화면 층

아래에서 위 순서로 겹칩니다. 위층이 아래층을 가립니다.

| 층 | 내용 | 비고 |
| --- | --- | --- |
| 배경 | 지금 보고 있는 가상 화면의 배경화면 | 패널 사이 간격과 반투명 패널 뒤로 보임 |
| 타일 | 분할 트리의 패널 | 서로 겹치지 않음 |
| 플로팅 | 그 가상 화면의 플로팅 패널 | 나중에 포커스한 패널이 위 |
| 전체화면 | 전체화면 또는 최대화한 패널 하나 | 타일과 플로팅을 가림 |
| 고정 | 고정 패널 | 모든 가상 화면, 전체화면 위 |
| 상단 바 | 가상 화면 목록, 레이아웃 표시, 상태 표시, 스크래치패드·명령 팔레트 버튼 | 전체화면 모드에서는 숨기고 상태 표시만 남김(3.3) |
| 스크래치패드 | 겹침 화면 | 뒤를 어둡게 함 |
| 명령 팔레트, 알림 | | 가장 위 |

상단 바의 상태 표시는 승인 대기 수, 입력 잠금, "이 기기만" 보기, 서버 연결 상태, 새 배분 중단입니다. 어느 배치 모드에서도 이 표시는 사라지지 않습니다.

### 3.2 동적 배치

패널을 열고 닫고 옮기면 그 가상 화면의 레이아웃 규칙으로 나머지 패널이 자동으로 다시 배치됩니다(요건 WS-10). 사용자가 빈 칸을 만들거나 메우지 않으며, 타일 층에는 빈 칸이 생기지 않습니다.

**dwindle**

- 새 패널은 포커스된 패널을 둘로 나눠 뒤쪽(오른쪽 또는 아래)에 들어갑니다. 비율의 기본값은 0.5이고 0.1~0.9 사이에서 조절합니다.
- 분할 방향은 나뉘는 패널이 가로로 길면 좌우, 아니면 상하입니다. 조작한 기기의 화면에서 정해 조작 메시지에 담아 보내고, 서버는 받은 방향을 트리에 저장합니다. 저장한 뒤에는 기기의 화면 비율이 달라도 방향이 바뀌지 않습니다(ADR 0022).
- 패널을 닫으면 형제가 부모의 자리를 그대로 차지합니다.
- 분할 방향 전환(좌우 ↔ 상하)과 두 쪽 맞바꾸기를 조작으로 둡니다.

**master**

- 분할 트리의 잎 순서에서 첫 패널이 주 패널이고, 나머지는 쌓임 영역에 같은 크기로 쌓입니다.
- 주 패널의 위치(왼쪽, 오른쪽, 위, 아래)와 비율(기본 0.55)은 가상 화면마다 정합니다.
- 새 패널은 쌓임 영역의 끝에 들어갑니다. "주 패널로 올리기"는 트리에서 두 잎을 맞바꿉니다.
- dwindle로 돌아가면 트리에 저장된 방향과 비율이 그대로 쓰입니다.

**크기 제한**

- 패널 종류마다 최소 크기가 있습니다(`시각 설계.md` 4장). 경계를 끌어도 최소 크기보다 작아지지 않습니다.
- 가상 화면 하나의 타일 패널 수에는 상한이 있습니다(측정 대기). 상한에 닿으면 새 패널은 플로팅으로 열립니다.
- 화면이 작아 어느 패널이 최소 크기를 지키지 못하면, 그 기기는 그 가상 화면을 좁은 화면 배치(5장)로 그립니다. 트리는 바꾸지 않습니다.

### 3.3 전체화면과 최대화

| 모드 | 모습 |
| --- | --- |
| 최대화 | 패널이 타일 영역 전체를 차지함. 상단 바, 바깥 간격, 둥근 모서리, 테두리는 그대로 |
| 전체화면 | 패널이 앱 창 전체를 차지함. 상단 바, 간격, 모서리, 테두리, 그림자가 없음 |

- 가상 화면마다 패널 하나만 최대화 또는 전체화면이 될 수 있습니다. 타일 패널과 플로팅 패널 모두 됩니다.
- 분할 트리와 플로팅 위치는 바뀌지 않으며, 풀면 원래 배치로 돌아갑니다.
- 모드 중에 포커스를 옮기면, 옮겨 간 패널이 같은 모드로 보입니다. 좁은 화면의 스와이프와 같은 모델입니다.
- 모드 중에 사용자가 새 패널을 열면 모드를 풀고 새 패널을 배치합니다. 실행 로그 패널처럼 자동으로 열리는 패널(BL-2)은 모드를 풀지 않고 뒤에서 배치되며, 상단 바의 상태 표시에 알립니다.
- 전체화면에서도 고정 패널, 스크래치패드, 명령 팔레트, 알림은 위에 보입니다. 상단 바는 숨기되 상태 표시(3.1)는 화면 위쪽 가장자리에 작은 알약 모양으로 남깁니다. 승인 대기(OR-2)와 입력 잠금 표시는 어떤 모드에서도 가려지지 않습니다.
- 전체화면에서 나가는 조작은 켤 때와 같은 키입니다. `Esc`는 터미널이 쓰므로 쓰지 않습니다. 터치는 위쪽 가장자리를 아래로 쓸어 상단 바를 잠시 불러낸 뒤 나갑니다.
- 전체화면 상태는 공유 상태입니다(ADR 0021). "이 기기만" 보기를 켠 기기는 따라가지 않습니다.
- 브라우저나 OS의 전체화면(F11 등)은 작업공간이 다루지 않습니다. 기기마다 동작이 달라 같은 경험(NF-7)으로 제공할 수 없기 때문입니다.

### 3.4 플로팅과 고정

**플로팅**

- 플로팅 패널은 그 가상 화면에만 있습니다.
- 위치와 크기는 타일 영역에 대한 비율(0~1)로 저장합니다. 기기마다 화면 크기가 다르기 때문입니다. 클라이언트는 최소 크기와 화면 밖으로 나가지 않도록 그릴 때 보정하며, 보정한 값을 서버에 되돌려 쓰지 않습니다.

**고정**

- 고정은 플로팅 패널에만 적용합니다. 타일 패널에 고정 조작을 하면 플로팅으로 바꾼 뒤 고정합니다.
- 고정 패널은 모든 가상 화면에서 같은 위치에 보이고, 전체화면을 포함한 모든 패널 위에 있습니다. 스크래치패드와 명령 팔레트보다는 아래입니다.
- 고정을 풀면 지금 보고 있는 가상 화면의 플로팅 패널이 됩니다. 가상 화면을 닫아도 고정 패널은 남습니다.
- 패널 머리에 고정 표시를 둡니다. 모든 패널 종류를 고정할 수 있고, 터미널 패널의 입력 소유권 규칙(4장)은 고정해도 같습니다.
- 고정 패널 수에는 상한이 있습니다(기본 3, 측정 대기).
- 쓰임새: 터미널을 전체화면으로 두고 프로세스 패널이나 실행 로그를 구석에 고정.

### 3.5 시각 효과와 배경화면

값과 구현 지침은 `시각 설계.md`가 정합니다. 화면 동작에 영향을 주는 규칙만 여기에 둡니다.

- **효과 수준**: `전체`, `절약`, `끔` 세 단계입니다. 기기마다 따로 고르며 서버가 기기별로 기억합니다(ADR 0023). 어느 수준에서도 기능과 조작은 같습니다(요건 WS-13).
- **OS 설정**: "동작 줄이기"가 켜진 기기는 애니메이션을, "투명도 줄이기"가 켜진 기기는 블러와 반투명을 끕니다. 효과 수준보다 우선합니다.
- **배경화면**: 전체 기본값 하나와, 가상 화면마다의 지정입니다. 가상 화면은 기본으로 대상마다 하나이므로, 배경화면으로 지금 어느 대상을 보고 있는지 구분할 수 있습니다. 공유 상태입니다.
- **이미지 등록**: 배경화면으로 쓸 이미지는 맥 호스트에서 `orch workspace wallpaper add`로만 등록합니다. 화면에는 올리기 기능을 두지 않고, 내장 배경과 등록된 이미지 중에서 고르기만 합니다(`보안 설계.md` 7장).
- **가독성**: 터미널, 실행 로그, diff 패널은 다른 패널보다 덜 투명합니다. 글자 대비 기준(`시각 설계.md` 6장)을 지키지 못하는 설정값은 받지 않습니다.

## 4. 조작

모든 동작은 키보드와 터치 양쪽으로 할 수 있습니다(요건 WS-6).

**키보드**: 리더 키 하나를 누른 뒤 명령 키를 누릅니다. Windows 키와 Super는 OS가 가로채므로 쓰지 않습니다. 기본 리더 키와 브라우저·OS가 가로채지 않는 명령 키 목록은 측정 대기(W-M6)이며, 단축키는 설정 파일로 바꿀 수 있습니다.

| 동작 | 키보드 | 터치 |
| --- | --- | --- |
| 가상 화면 전환 | 리더 + 숫자 | 가상 화면 목록에서 선택, 가장자리 스와이프 |
| 패널 열기 | 리더 + 패널 종류 키 | 명령 팔레트 |
| 패널 닫기 | 리더 + 닫기 키 | 패널 메뉴 |
| 포커스 이동 | 리더 + 방향키 | 패널 탭, 좁은 화면에서는 스와이프 |
| 플로팅·고정 패널로 포커스 이동 | 리더 + 플로팅 포커스 키 | 패널 탭 |
| 패널 자리 바꾸기 | 리더 + Shift + 방향키 | 패널 머리를 끌어 다른 패널 위에 놓기 |
| 분할 비율 조절 | 리더 + 크기 조절 모드 | 경계 드래그 |
| 분할 방향 전환, 두 쪽 맞바꾸기 (dwindle) | 리더 + 방향 전환 키, 맞바꾸기 키 | 패널 메뉴 |
| 주 패널로 올리기 (master) | 리더 + 올리기 키 | 패널 메뉴 |
| 레이아웃 전환 (dwindle, master) | 리더 + 레이아웃 키 | 명령 팔레트 |
| 최대화 | 리더 + 최대화 키 | 패널 머리 두 번 탭, 패널 메뉴 |
| 전체화면 | 리더 + 전체화면 키 | 패널 메뉴, 명령 팔레트 |
| 플로팅 전환 | 리더 + 플로팅 키 | 패널 메뉴 |
| 플로팅 패널 이동과 크기 조절 | 리더 + 크기 조절 모드 | 패널 머리 드래그, 모서리 드래그 |
| 고정 전환 | 리더 + 고정 키 | 패널 머리의 고정 버튼, 패널 메뉴 |
| 스크래치패드 열고 닫기 | 리더 + 스크래치패드 키 | 상단 버튼, 아래에서 위로 쓸어 올리기 |
| 명령 팔레트 | 리더 + 팔레트 키 | 상단 버튼 |
| 모양 설정 (배경화면, 효과 수준) | 명령 팔레트 | 명령 팔레트 |

**터미널 입력(터치 기기)**: 화면 키보드 위에 Ctrl, Esc, Tab, 방향키를 담은 보조 키 줄을 둡니다. iPad의 하드웨어 키보드가 연결되면 키보드 입력을 그대로 보냅니다(요건 WS-9).

**입력 권한과 입력 소유권** (`보안 설계.md` 4장)

- 터미널 입력은 `입력` 권한을 가진 기기만 할 수 있습니다. `보기` 기기의 터미널 패널에는 보조 키 줄과 입력 칸을 두지 않고, 권한이 없다는 표시만 둡니다.
- 터미널 패널마다 입력 소유 기기가 하나입니다. 패널 머리에 소유 기기 이름을 보이고, 다른 기기는 패널 메뉴나 명령 팔레트의 "입력 가져오기"로 소유권을 옮깁니다. 옮기면 이전 소유 기기에 알립니다.
- 소유하지 않은 기기에서 입력하면 서버가 거부하고 그 기기에만 알립니다.
- 입력 잠금(`orch workspace lock`) 중에는 모든 터미널 패널 머리에 잠금 표시를 두고 입력 칸을 막습니다. 화면에서 잠금을 풀 수 없습니다.
- 창의 프로세스가 끝난 터미널 패널은 읽기 전용으로 바뀌고 끝났다는 표시를 둡니다.

**배치와 모양 조작의 권한**: 배치(패널 열고 닫기, 전체화면, 고정)와 모양(배경화면 고르기)은 `보기` 기기도 할 수 있습니다. 터미널에 키를 보내지 않기 때문입니다. 효과 수준은 자기 기기 것만 바꿉니다.

**"이 기기만" 보기**: 명령 팔레트로 켜면 이 기기는 공유 상태의 가상 화면 전환, 포커스, 전체화면 상태를 잠시 따라가지 않고, 이 기기의 조작도 다른 기기에 보내지 않습니다. 화면 위쪽에 켜져 있다는 표시를 두고, 끄면 공유 상태로 돌아옵니다. 모든 기기에 같은 조작으로 있습니다.

## 5. 기기별 배치

| 화면 | 배치 |
| --- | --- |
| 넓은 화면 (Windows, iPad 가로·세로) | 분할 트리를 그대로 타일로 그림 |
| 좁은 화면 (iPhone 세로) | 같은 분할 트리에서 포커스된 패널 하나를 전체 화면으로 그림. 스와이프는 트리 순서상 옆 패널로 포커스를 옮김. 트리 자체는 바꾸지 않음 |
| 공통 | 같은 패널 종류, 같은 명령, 같은 공유 상태. 기기별 전용 기능 없음 |

iPhone에서 포커스를 옮기면 공유 상태에 따라 다른 기기의 포커스도 옮겨집니다.

**좁은 화면에서의 배치 모드**

| 개념 | 좁은 화면에서의 모습 |
| --- | --- |
| 최대화 | 늘 패널 하나를 그리므로 모습이 같음. 상태는 그대로 공유 |
| 전체화면 | 상단 바를 숨기고 상태 표시만 남김 |
| 플로팅 | 스와이프 순서에서 타일 패널 뒤에 이어짐 |
| 고정 | 화면 아래 고정 줄에 패널마다 칩 하나. 모든 가상 화면에서 보이며, 누르면 화면 절반 높이의 시트로 열림 |
| 간격, 모서리, 그림자 | 패널이 화면을 채우므로 바깥 간격과 모서리를 두지 않음. 시트와 스크래치패드에는 둠 |
| 배경화면 | 시트 뒤와 가상 화면 전환 중에 보임. 화면을 채우도록 잘라 그림 |

## 6. 인수 시나리오 (NF-7 출시 조건)

v1은 Windows, iPhone, iPad 세 기기에서 아래 시나리오를 모두 통과해야 출시합니다.

1. 접속과 인증: Tailscale 안에서 접속하고, 허용되지 않은 기기는 거부됨
2. 가상 화면: 대상별 가상 화면이 보이고 전환됨. 한 기기의 전환이 다른 기기에 반영됨
3. 패널: 각 v1 패널을 열고 닫고, 포커스를 옮기고, 분할 비율을 바꿈
4. 터미널: 메인 Claude Code 창에 입력하고 출력이 모든 기기에 보임. 터치 기기에서 보조 키 줄로 Ctrl·Esc·방향키 입력
5. 실시간 갱신: 작업 상태가 바뀌면 보드와 로그 패널이 갱신됨. 연결을 끊었다 다시 붙으면 놓친 이벤트가 채워짐
6. 승인 대기: 메인이 권한 승인을 기다리면 스크래치패드에 표시되고, 누르면 메인 터미널로 이동함
7. 재접속: 화면 잠금·앱 전환 뒤 다시 열면 같은 상태로 돌아옴
8. 비공개 정보: 화면 어디에도 토큰, 알림 토픽, 개인 경로가 나오지 않음. 연결을 끊은 뒤 기기의 브라우저 저장소에 로그와 diff가 남지 않음
9. 입력 권한: `보기` 기기는 터미널에 입력할 수 없음. 소유하지 않은 기기의 입력은 거부되고 그 기기에 알림이 옴. 입력마다 감사 기록이 남고 내용은 남지 않음
10. 입력 잠금: `orch workspace lock` 뒤 모든 기기의 입력이 거부되고, 화면에서 풀 수 없음. 서버를 다시 띄워도 잠금이 유지됨
11. 셸 복귀 없음: 메인 Claude Code를 끝낸 창의 패널이 읽기 전용이 되고 셸 프롬프트가 나오지 않음
12. 동적 배치: 패널 다섯 개를 차례로 열고 둘을 닫는 동안 타일 층에 빈 칸이 생기지 않음. dwindle과 master를 오가도 패널과 dwindle의 방향·비율이 유지됨. 넓은 화면 두 기기에서 분할 방향이 같음
13. 전체화면: 최대화와 전체화면을 켜고 끔. 다른 기기에 반영되고, 풀면 원래 배치로 돌아옴. 전체화면 중에 승인 대기가 생기면 상태 표시와 스크래치패드로 알 수 있고, 실행 로그가 자동으로 열려도 전체화면이 풀리지 않음
14. 고정: 패널을 고정하면 모든 가상 화면과 전체화면 위에 보임. 좁은 화면에서는 고정 줄에서 열림. 고정을 풀면 지금 가상 화면의 플로팅 패널이 됨
15. 모양: 배경화면을 바꾸면 모든 기기에 반영됨. 효과 수준을 `끔`으로 하면 그 기기만 그림자·블러·애니메이션 없이 같은 기능으로 동작함. OS의 "동작 줄이기"를 켜면 애니메이션이 꺼짐
16. 가독성: 가장 밝은 내장 배경과 흰색 시험 이미지 위에서 터미널·로그·diff·보드의 글자가 대비 기준(`시각 설계.md` 6장)을 지킴
