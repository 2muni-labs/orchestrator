# 0022. 깊은 리뷰가 스스로 머지하고 user-approved는 머지 거부·보류에만 씀

- 상태: 결정됨
- 날짜: 2026-11-17
- 관련 문서: 요건 정의 2장·9장, 기술 설계 4.7.1, 보안 설계 11장, `config/main.md` Merge policy
- 대체: ADR 0020의 `verify-deep` 머지 조건과 `user-approved`의 뜻, ADR 0021의 "사용자가 새 리뷰 뒤에 다시 승인"

## 맥락

ADR 0020에서 `verify-deep` PR은 깊은 리뷰가 통과해도 사용자가 `user-approved`를 붙여야 머지되었습니다. 하네스 PR과 L3 작업은 모두 `verify-deep`이므로 거의 모든 PR에 사용자 개입이 필요했고, ADR 0021로 main이 움직일 때마다 다시 승인해야 했습니다. 깊은 리뷰가 문제를 찾지 못한 PR에서 사용자의 승인은 리뷰 결과를 그대로 따르는 일이 대부분이었습니다.

## 선택지

1. ADR 0020대로 모든 `verify-deep` PR에 사용자 승인을 요구합니다.
2. 깊은 리뷰가 문제가 없다고 판정하면 스스로 머지하고, 사용자는 리뷰가 머지를 거부하거나 판정을 보류한 PR에만 개입합니다.

## 결정

2를 택합니다.

- `verify-deep`: 깊은 리뷰 예약 작업이 리뷰 뒤 문제가 없으면 스스로 승인하고 merge commit으로 머지합니다. `user-approved`는 더 이상 `verify-deep`의 머지 조건이 아닙니다.
- 판정: 가벼운 리뷰는 머지, 머지 거부, 수정 요구, 상향입니다. 깊은 리뷰는 머지, 머지 거부, 수정 요구, 보류입니다. 머지 거부와 보류는 `needs-user`를 붙입니다. 보류는 안전 장치 영향을 diff만으로 판정할 수 없을 때입니다.
- `user-approved`: 판정이 머지 거부나 보류인 PR에 사용자가 붙이면 사용자 승인 머지 예약 작업이 머지합니다. 조건은 라벨 행위자가 사용자, 라벨 뒤 push 없음, 현재 head의 최신 판정이 머지 거부나 보류, 필수 체크 통과, `review-overridden` 없음입니다. 판정 코멘트는 작성자가 사용자 계정인 것만 인정합니다. 봇은 계속 이 라벨을 붙이거나 떼지 않습니다.
- `review-overridden`은 지금처럼 사용자가 직접 머지합니다.

## 결과

- 안전 장치 경로의 변경도 사용자 확인 없이 머지됩니다.
- 봇 키가 유출되면 방어선은 필수 체크와 깊은 리뷰의 판정입니다. ADR 0020에서 `verify-deep` PR에 있던 사용자 승인이라는 방어선은 머지 거부와 보류에만 남습니다.
- 워크플로 파일은 봇이 push할 수 없으므로(ADR 0020), 필수 체크 자체는 봇이 바꿀 수 없습니다.
- 사용자의 개입은 `needs-user`(머지 거부, 보류), 두 번째 `changes-requested`, `review-overridden` PR의 머지로 줄어듭니다. main이 움직여 다시 리뷰한 `verify-deep` PR도 판정이 머지면 사용자 없이 머지됩니다.
- 예약 작업은 정책을 `origin/main`의 `config/main.md`에서 읽습니다. 이 결정은 머지된 뒤부터 적용됩니다.
