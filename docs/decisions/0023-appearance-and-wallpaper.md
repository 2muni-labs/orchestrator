# 0023. 모양 설정의 공유 범위와 배경화면 이미지 등록

- 상태: 제안 (머지할 때 "결정됨"으로 바꿈)
- 날짜: 2026-11-17
- 관련 문서: 요건 WS-13, WS-14, `화면 설계.md` 3.5, `시각 설계.md`, `보안 설계.md` 7장, 기술 설계 4.15

## 맥락

그림자, 블러, 배경화면을 더합니다. 세 가지를 정해야 합니다.

- 모양 설정을 기기 사이에 공유할지. 화면 상태는 서버가 가지고 클라이언트는 기기에 저장하지 않습니다(ADR 0007, `보안 설계.md` 7장).
- 기기마다 그리기 성능이 다릅니다. 블러와 애니메이션은 측정 대상입니다(W-M6).
- 배경화면 이미지를 어디서 받을지. 작업공간 서버는 샌드박스 프로필 안에서 돌고(`보안 설계.md` 5장), 서버 골격은 안전 장치 경로입니다.

## 선택지

공유 범위

1. 모두 공유
2. 모두 기기별
3. 모양(배경화면, 불투명도, 강조색, 간격)은 공유, 효과 수준만 기기별

이미지 등록

- A. 맥 호스트의 orch 명령으로만 등록, 화면에서는 고르기만
- B. `입력` 권한 기기의 화면에서 올리기
- C. 모든 기기의 화면에서 올리기

## 결정

공유 범위는 3, 이미지 등록은 A를 택합니다.

- 효과 수준(`전체`, `절약`, `끔`)은 기기마다 고르고, 서버가 기기 신원별로 기억합니다. 어느 수준에서도 기능과 조작은 같으므로 "기기별 전용 기능 없음"(요건 NF-7)에 어긋나지 않습니다.
- 배경화면은 전체 기본값과 가상 화면별 지정을 공유합니다.
- 이미지는 `orch workspace wallpaper add`로 맥 호스트에서만 등록합니다. 입력 권한 변경과 잠금 해제를 호스트에서만 하는 것과 같은 원칙입니다(`보안 설계.md` 4장).
- 블러는 타일 패널에는 미리 흐리게 한 배경화면을, 겹치는 요소에만 실시간 블러를 쓰는 방식을 기본안으로 하고 측정으로 확정합니다.

B와 C를 택하지 않은 이유: 서버에 파일을 받는 길이 새로 생기고, 서버 프로필에 쓰기 경로가 더해집니다. 배경화면은 자주 바꾸지 않으므로 v1에서 그 위험을 질 이유가 없습니다.

## 결과

- 서버는 배경화면 디렉터리를 읽기만 합니다. 서버 프로필에 쓰기 경로가 늘지 않습니다.
- 새 이미지를 쓰려면 맥에 파일을 옮기고 명령을 실행해야 합니다. 화면에서 올리기는 v2에서 다시 검토합니다.
- 서버에 기기별 설정 저장이 생깁니다. 기기를 가리는 키는 Tailscale 신원을 씁니다(W-M7).
- 디자인 시제품(W-M6)의 측정 범위에 그림자, 배경화면 이미지, 고정 패널, 전체화면 전환이 들어갑니다.
