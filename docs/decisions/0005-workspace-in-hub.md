# 0005. 작업공간을 같은 저장소에 둠

- 상태: 결정됨
- 날짜: 2026-11-15
- 관련 문서: 요건 1장, 12장

## 맥락

orch에 화면(작업공간)을 더하려 할 때, 별도 저장소로 둘지 허브에 둘지와 이름을 정해야 했습니다.

## 선택지

1. 별도 저장소와 버전을 붙인 출력 계약
2. 서브모듈
3. 같은 저장소의 구성 요소, 경계는 출력 계약과 import 금지 테스트로 유지

## 결정

3을 택합니다. orch는 파이프라인, 운용 관리, 작업공간으로 이뤄집니다. 서비스 이름은 두지 않고 기능 명칭 "작업공간(화면 출력부)", 식별자 `workspace`(`orch workspace`, `workspace/`, `schemas/workspace/`, 테스트 묶음 `workspace`)를 씁니다.

## 결과

- 한 PR에서 계약과 소비자를 함께 바꿀 수 있습니다.
- 작업공간은 `state.db`에 쓰지 않고, 파이프라인은 작업공간을 import하지 않습니다. 둘 다 테스트로 고정합니다.
- 작업공간의 의존성이 허브에 들어오므로 의존성 정책(`보안 설계.md` 6장)이 필요해졌습니다.
