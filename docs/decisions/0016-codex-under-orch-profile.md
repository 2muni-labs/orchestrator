# 0016. Codex는 자체 샌드박스를 끄고 orch 프로필 안에서

- 상태: 결정됨
- 날짜: 2026-11-15
- 관련 문서: `보안 설계.md` 5장, 기술 설계 4.6, 4.16

## 맥락

측정(S-M2, codex-cli 0.160.0)에서 Codex의 `read-only`와 `workspace-write`는 워크트리 밖을 읽었습니다. `~/.orch` 아래의 가짜 비밀 파일과 `~/.orch/config`도 읽었습니다. 바깥 `sandbox-exec`로 감싸면 Codex 자체 샌드박스가 시작하지 못합니다(중첩 실행은 종료 코드 71). 그런데 Codex는 명령을 하나도 실행하지 않은 채 종료 코드 0으로 끝나고, 일을 마쳤다고 답했습니다. `--sandbox danger-full-access`를 orch 프로필 안에서 쓰면, 가짜 비밀 읽기와 쓰기, 워크트리 밖 쓰기는 거부되고 워크트리 안 쓰기와 탐색 답은 정상이었습니다(E8, E9).

## 선택지

1. Codex 자체 샌드박스를 끄고 orch 프로필을 유일한 샌드박스로 씀. 리뷰, `orch explore`, B 레인 구현 모두
2. 1을 리뷰와 `orch explore`에만 먼저 적용하고, B 레인 구현은 1주일 무인 운용 뒤에 적용
3. Codex 설정으로 읽기 범위를 좁힘

## 결정

1을 택합니다. 2는 무인 운용 기간에 구현 서브가 `~/.orch`를 읽을 수 있는 위험을 남깁니다. 3은 0.160.0에서 읽기 범위를 좁히는 설정이 측정되지 않았고, 그렇게 해도 실행 결과가 Codex의 판단에 달려 있습니다.

## 결과

- `m-p5-codex-sandbox`(M19, L3)가 Codex 실행 세 곳을 모두 바꿉니다. 프로필은 게이트 프로필에서 출발하고, Codex가 쓰는 `~/.codex`의 쓰기와 인증 파일 읽기를 허용합니다. `~/.orch/secrets`, `~/.orch/config`, 다른 대상의 런타임 디렉터리는 거부합니다. 리뷰와 탐색은 `-o` 경로 말고는 쓰기를 모두 거부합니다.
- 프로필이 거부하는지는 실제 `sandbox-exec`로 테스트합니다(요건 NF-2).
- 명령 실행이 기대되는 실행에서 명령 실행 이벤트가 하나도 없으면, 종료 코드가 0이어도 성공으로 보지 않습니다.
- Codex 버전을 올릴 때 S-M2를 다시 측정합니다(`config/pins.toml`).
