# 0004. Phase 5의 정의와 5a·5b 분할

- 상태: 결정됨
- 날짜: 2026-11-15
- 관련 문서: 구축 절차 4.3, 요건 12장

## 맥락

Phase 4에서 샘플 대상으로 외부 저장소 검증을 마쳤습니다. 다음 단계로 실제 대상 등록과 작업공간 개발이 후보였습니다. 작업공간 계획을 외부 리뷰한 결과, 작업공간(원격 터미널을 포함하는 큰 공격 면)과 운용 점검을 한 단계에 묶으면 장애 원인을 가르기 어렵다는 지적이 있었습니다.

## 선택지

1. 다른 실제 저장소를 등록해 운용
2. 허브에서 작업공간을 개발하며 1주일 이상 무인 운용(한 단계)
3. 2를 운용 점검(5a)과 작업공간(5b)으로 나눔

## 결정

Phase 5는 허브에서 작업공간을 개발하며 1주일 이상 무인 운용하는 단계입니다. 다른 실제 대상 저장소 등록은 Phase 6으로 미룹니다. 이를 둘로 나눕니다.

- **5a 운용 점검**: M17~M19와 현재 tmux 구성으로 1주일 무인 운용
- **5b 작업공간**: M20~M21

5a 직후 실제 대상 하나를 등록할지는 5a를 마칠 때 정합니다(요건 13장).

## 결과

- 무인 운용 중의 장애는 파이프라인 확장만의 문제로 좁혀집니다.
- 작업공간 서버는 5a의 운용 결과와 보안 측정(S-M1~S-M3) 뒤에 시작합니다.
- 기기 분실 런북(`보안 설계.md` 9장)은 5a의 1주일 운용 전에 갖춥니다.
