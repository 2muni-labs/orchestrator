# 0019. 고정 버전 대신 selfcheck를 통과한 최신 버전을 따름

- 상태: 결정됨
- 날짜: 2026-11-16
- 관련 문서: 기술 설계 4.13·5.2·5.3, 실행 설계 6장 환경 전제, 구축 절차 4.3, `config/pins.toml`

## 맥락

지금은 Claude Code(2.1.319)와 Codex(0.160.0)를 고정하고, 버전을 올릴 때마다 사람이 다시 측정한 뒤 PR로 고정 버전을 바꿉니다. guard, 훅의 차단 방식, Codex 격리와 프록시 같은 안전 장치가 측정한 도구 동작에 기대고 있기 때문입니다. 그런데 새 기능(예: Claude Code 2.1.323 이상의 Code Mode)을 쓰려면 버전을 자주 올려야 하고, 재측정을 사람이 매번 하면 그만큼 늦어집니다. 반대로 검사 없이 자동 업데이트를 켜면 도구 동작이 조용히 바뀌어 안전 장치가 꺼질 수 있습니다.

설치 방식 측정(FL-M1·FL-M2, 2026-11-16, 격리 HOME, `~/.orch/<대상>/measure/fl/`):
- `claude install <버전>`은 `versions/<버전>`에 내려받는 즉시 `~/.local/bin/claude` 링크를 새 버전으로 바꿉니다. 릴리스마다 `manifest.json`에 플랫폼별 sha256과 크기가 있고, 내려받은 바이너리의 sha256이 일치했습니다. `manifest.json.sig`도 있습니다(형식은 아직 보지 않음). 새 바이너리는 링크를 거치지 않고 절대 경로로 실행됐습니다.
- `mise install codex@<버전>`(aqua 백엔드)은 활성 버전을 바꾸지 않습니다. lock 파일을 켜 두었어도 새 버전의 체크섬을 lock에 넣지 않습니다.
- `mise lock`은 설치하지 않고 새 버전의 체크섬과 주소를 lock에 쓰지만, 이전 버전 항목을 lock에서 지웁니다. lock의 체크섬을 틀리게 바꾸면 `mise install`이 불일치로 거부했습니다(종료 코드 1).
- HOME을 바꿔도 작업 디렉터리가 실제 홈 아래면 mise는 위쪽 디렉터리를 따라 실제 `~/.config/mise/config.toml`을 읽었습니다.

## 선택지

1. 지금처럼 고정하고 사람이 재측정한 뒤 PR로 올림
2. 도구의 자동 업데이트를 켬
3. orch가 새 버전을 옆에 설치하고, 자동화할 수 있는 재측정 항목을 새 바이너리로 돌려 통과할 때만 전환함(selfcheck)

## 결정

3을 택합니다. 1은 느리고, 2는 안전 장치의 전제를 검사 없이 바꿉니다. 3은 전제를 매번 기계적으로 확인하면서 최신을 따릅니다.

- 확인 시점은 새 세션 시작(`orch open`)과 수동 `orch selfcheck`입니다. 주기 실행은 두지 않습니다.
- Claude Code의 자체 자동 업데이트는 계속 끕니다(`DISABLE_AUTOUPDATER=1`). 설치와 전환은 selfcheck만 합니다. `claude install`은 설치 즉시 전환하므로 쓰지 않고, orch가 manifest의 sha256을 확인하며 `versions/<버전>`에 직접 내려받은 뒤 통과하면 링크를 원자적으로 바꿉니다.
- Codex는 config와 lock의 복사본으로 `mise lock`을 먼저 해 체크섬을 기록하고, 그 lock으로 설치합니다. mise는 홈 밖의 작업 디렉터리에서 실행하고, 읽는 설정이 복사본뿐인지 확인한 뒤 진행합니다. 통과하면 실제 config와 lock을 바꾸고, 실행 경로는 고정 링크 `~/.orch/bin/codex`를 옮깁니다. `~/.orch/config`의 Codex 경로는 이 링크를 가리키며, mise shim은 쓰지 않습니다.
- 실패하면 이전 버전을 그대로 쓰고, 새 배분과 실행을 멈추며(일시 정지 사유) 알림을 보냅니다.
- 자동화할 수 없는 재측정 항목(P5-M4 권한 대기 이벤트, S-M1 tmux와 `!` 모드 등)은 경고만 하고 전환을 막지 않습니다.
- `config/pins.toml`의 `version`은 "마지막으로 검증된 버전"이고, 재측정 항목은 selfcheck의 검사 목록입니다. 규칙의 "고정 버전에서 측정"은 "검증된 버전에서 측정"으로 바꿉니다.

## 결과

- 작업 `m-selfcheck`(B, L3)가 구현합니다. 그 뒤 버전 PR과 설치, 전환(자동 추종 시작, Code Mode 설정)을 거쳐 M17로 갑니다.
- 지시서를 쓰기 전에 확인할 것: `manifest.json.sig`의 형식과 검증 방법, mise에 복사본 설정만 읽히는 방법(환경 변수나 인자)의 실측.
- 실제 mise 설정과 lock은 사용자의 개인 설정 저장소를 가리키는 링크입니다. selfcheck가 바꾼 내용은 그 저장소의 미커밋 변경으로 남으므로 결과에 알립니다.
- 남은 위험: 재측정 항목에 없는 동작 변화는 잡지 못합니다. 새 안전 장치를 만들면 그 전제를 재측정 항목에 함께 추가합니다.
