# 0012. Codex 우선 배분

- 상태: 결정됨
- 날짜: 2026-11-15
- 관련 문서: 요건 3장, 4장, 구축 절차 4.3, 기술 설계 4.16

## 맥락

Claude 사용량이 병목입니다. 최근 7일 측정에서 메인 Opus 세션이 Claude 사용량의 90% 이상(cache read 269.8M, cache write 5.23M, output 1.31M 토큰)이었고, Codex 주간 사용률은 19%였습니다.

## 선택지

1. 등급별 레인 배정 유지
2. 구현은 등급과 관계없이 B 레인(Codex), 탐색도 Codex로 옮김

## 결정

2를 택합니다.

- 구현은 등급과 관계없이 B 레인이 기본이며, L3 위험 영역도 xhigh로 B에 보냅니다. C 레인은 Codex 잔여가 부족하거나 사용자가 Claude를 지정한 작업에만 씁니다.
- L3는 지시서의 위험이 실제로 요구할 때만 씁니다.
- 탐색과 사실 확인은 Codex 잔여가 충분하면 `orch explore`(M19)를 먼저 쓰고, 부족하면 `orch-explorer`를 씁니다. 근거가 되는 사실은 메인이 파일·줄 범위로 직접 확인합니다.
- `[limits] total`은 3, B 상한은 M18 뒤 3입니다.

## 결과

- Codex가 읽는 범위가 넓어집니다. Codex의 `read-only`·`workspace-write` 샌드박스가 디스크 전체를 읽을 수 있는지 측정하고(S-M2), 필요하면 orch 프로필로 감쌉니다(`보안 설계.md` 5장).
- Codex 답은 데이터로만 다룹니다(`보안 설계.md` 8장).
