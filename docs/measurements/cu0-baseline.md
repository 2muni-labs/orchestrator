# CU0 기준선 (`cu0-baseline`)

ADR 0027 결정 6의 기준선입니다. CU6(#155)는 같은 스크립트와 같은 계산법으로 시범 기간을 재고 이 값과 비교합니다. 관련 이슈: #149(CU0), #529.

- 측정: 2026-11-19 UTC, 허브 `main` `f474788`, 설치된 orch v0.18.0, 메인 에이전트
- 스크립트: `scripts/usage_baseline.py`(읽기 전용, 표준 라이브러리만, 집계 수치만 JSON으로 출력)
- 원천: `~/.orch/state.db`(tasks, events, runs), GitHub의 머지 시각, Claude Code 트랜스크립트(`~/.claude/projects`), Codex 세션 파일(`~/.codex/sessions`)

## 재현 방법

```
GH_TOKEN=$(~/.orch/bin/ghapp-token.sh) gh pr list -R 2muni-labs/orchestrator \
  --state merged --limit 300 --json headRefName,mergedAt > <scratchpad>/merged.json
ORCH_HUB=<hub clone> .venv/bin/python -I scripts/usage_baseline.py \
  --start 2026-11-05 --end 2026-11-20 --split 2026-11-17 --merged-json <scratchpad>/merged.json
```

`--start`·`--end`는 UTC 날짜이며 `--end`는 포함하지 않습니다. 사용량 창은 `--start 2026-11-12`로 한 번 더 실행합니다. 스크립트는 네트워크와 토큰을 쓰지 않으므로 머지 시각은 따로 받아 파일로 넘깁니다. 출력에는 경로, 작업 id, 세션 id, 계정 필드가 들어가지 않습니다.

## 기간과 표본

| 창 | 기간 (UTC) | 표본 | 쓰는 지표 |
| --- | --- | --- | --- |
| 전체 창 | 2026-11-05 ~ 2026-11-19 | `orchestrator` 대상에서 이 기간에 만든 작업 68개 (L2 17, L3 51). 모두 B 레인 `gpt-6.1-sol`(L2 `medium`, L3 `high`). 측정 시점에 열린 작업 없음 | 완료 수, 재작업, 단계별 시간 |
| 사용량 창 | 2026-11-12 ~ 2026-11-19 | 작업 29개 (L2 8, L3 21), 실행 30회 | 위 지표와 Claude·Codex 원시 토큰 |

- 사용량 창을 따로 둔 이유: Codex 구현 실행의 세션 파일이 11-12부터만 남아 있습니다. 11-12 전의 실행 38회는 Codex 토큰을 셀 수 없습니다.
- PR 대기는 11-17을 경계로 나눕니다. 그 전에는 사용자가 머지했고, 11-17부터는 라벨로 시작하는 클라우드 리뷰 작업이 머지합니다(ADR 0022, v0.15.0).
- 같은 전체 창에 머지된 PR 120개 중 67개는 작업이 없는 PR(하네스·문서)입니다. 메인 사용량에는 이 작업도 들어 있습니다.
- 오늘(11-19)은 측정 시각까지만 들어 있습니다.

## 계산법

| 지표 | 계산 |
| --- | --- |
| 완료 수 | 상태가 `closed`인 작업 |
| 폐기 | 상태가 `discarded`인 작업. 이 기간의 폐기는 모두 새 id로 다시 배분됨 |
| 실행 결과 | `runs.outcome`이 `DONE`이 아닌 실행을 `outcome:failure_reason`별로 셈 |
| 재작업 전이 | events의 `gating→judging`(게이트 실패), `reviewing→judging`(G4 BLOCK), `judging→reserved`(retry), `blocked→reserved`(resume) 횟수 |
| 재작업 없는 완료 | 완료 작업 중 실행이 모두 `DONE`이고 재작업 전이가 없는 것 |
| 준비 시간 | 작업 생성(`orch prepare`)부터 첫 `prepared→reserved/queued`(`orch dispatch`)까지. 메인의 테스트 커밋 작성과 사용자 확인 대기가 들어 있음 |
| 실행 시간 | `reserved→running`부터 `running→judging`까지 |
| 판정 지연 | `running→judging`부터 첫 `judging→gating`까지 |
| G4 리뷰 | `gating→reviewing`부터 `reviewing→ready/judging`까지 |
| PR 대기 | `ready→pr_open`부터 GitHub `mergedAt`까지 (`task/<id>` 브랜치) |
| 준비→머지 | 작업 생성부터 GitHub `mergedAt`까지 (시간) |
| 시간 요약 | 분 단위의 표본 수, 중앙값, p90(nearest-rank), 최댓값 |
| Claude 원시 토큰 | 트랜스크립트의 assistant 항목 `usage`를 `requestId`로 중복 제거하고 `timestamp`가 창 안인 것만 합산. 허브 프로젝트 디렉터리의 최상위 파일은 메인, `subagents/` 아래는 서브, 다른 프로젝트는 기타 |
| Codex 원시 토큰 | 세션 파일마다 마지막 `total_token_usage`. `session_meta`의 시작 시각이 창 안인 것만. `source`가 `exec`이고 `cwd`가 대상 워크트리 아래면 구현 실행, 그 밖의 `exec`은 기타 exec, 나머지는 대화형 |
| Codex 주간 한도 | `rate_limits.secondary.used_percent`의 창 안 최댓값을 리셋 시각별로. **원시 토큰과 다른 지표**이며 계정 전체 값 |

## 미측정 항목과 한계

- **Claude 구독 한도 %**: 로컬에서 읽을 원천이 없습니다. 원시 토큰으로 추정하지 않습니다.
- **지시서 작성 시간**: `orch prepare` 전의 작업이라 기록이 없습니다. 준비 시간은 테스트 커밋 작성부터만 셉니다.
- **11-12 전 Codex 토큰**: 세션 파일이 없습니다.
- **작업별 Claude 토큰**: 메인 세션 하나가 여러 작업과 하네스 작업을 함께 하므로 작업 단위로 나눌 수 없습니다.
- **Codex 주간 한도의 연속 값**: 세션이 남긴 시점의 값만 있어서, 창 안 최댓값은 실제 최댓값보다 낮을 수 있습니다.
- **재작업의 원인 분류**: 폐기 18건의 원인(테스트 오류, 지시서 오류, 구현 결함)은 상태 기록만으로 나눌 수 없어 세지 않았습니다.

## CU6 비교 규칙

- 같은 스크립트와 옵션으로 시범 기간을 재고, 등급별로 비교합니다. 표본이 이 기준선보다 크게 작으면 성공을 선언하지 않고 기간을 늘리거나 판단을 보류합니다(#155).
- 원시 토큰과 구독 한도 %는 서로 바꿔 쓰지 않습니다.
- 시범 중단 기준은 ADR 0027 결정 6을 따릅니다. 중복 실행, 승인 범위 이탈, 테스트나 지시서 변경 누락이 한 번이라도 나오면 drain의 자동 시작을 멈춥니다.
